# 需求池插件开发验证包

适用基线为禅道开源版 22.7。当前验证页供管理员验证收件、负责人分派及状态变更。

在仓库根目录生成 ZIP：

```sh
python3 plugins/reqintake/build.py /tmp/reqintake.zip --sha256
(cd /tmp && sha256sum -c reqintake.zip.sha256)
unzip -t /tmp/reqintake.zip
```

在隔离的禅道测试实例中，从后台扩展管理本地安装 ZIP。管理员登录后，默认 Compose 的 PATH_INFO 模式使用 `/reqintake-index.html`，GET 路由模式使用 `/index.php?m=reqintake&f=index`。

基线镜像中的扩展目录由 root 拥有。只在一次性测试容器中，可在本地安装前给 PHP 进程开放安装器需要的目录：

```sh
docker compose exec -u root php sh -c 'mkdir -p /var/www/zentao/extension/pkg && chown www-data:www-data /var/www/zentao/extension /var/www/zentao/extension/pkg /var/www/zentao/extension/custom'
```

这些权限和解包后的插件文件位于当前 PHP 容器内，重建后需重新准备。数据库中的安装记录会随数据库卷保留。

验证收件时，先使用未配置负责人的产品登记，确认列表显示实际负责人为提报人并标为待配置。再配置具有该产品访问权限的账号，确认新件分派给该账号。关闭及重开时须填写原因。分别用两个页面打开同一状态，在一个页面修改后，从另一个页面提交并检查是否提示记录已变化。

源码可用以下命令验证能否继承当前基线的框架类：

```sh
php -r 'require "framework/control.class.php"; require "framework/model.class.php"; require "plugins/reqintake/extension/custom/reqintake/control.php"; require "plugins/reqintake/extension/custom/reqintake/model.php";'
```

已安装插件后，可在使用简体中文和 GET 路由的隔离实例中运行 HTTP 回归。先建立名为 `Smoke Product` 的测试产品，并保持未配置负责人；测试会产生一条反馈并执行状态流转。

```sh
python3 plugins/reqintake/tests/smoke.py http://127.0.0.1:8097 /path/to/test-admin-password
```

管理员可在禅道权限组中为普通账号授予需求池的列表和详情权限。列表权限包括登记反馈，用户只能查看有权访问的产品。实际负责人可办理已分派的反馈，临时跟进人和其他用户无权变更状态。负责人配置仍由管理员管理。

从开发版 0.1.0 升到 0.2.0 前，请在维护窗口用数据库管理工具执行 `db/install.sql`。如果实例使用其他表前缀，先把脚本中的 `zt_reqintake` 改为实际前缀加 `reqintake`。该脚本只创建缺失的表；确认关联表存在后再上传 ZIP 并升级。首次安装由禅道执行建表脚本。

可重复传入 `--target TYPE ID` 来检查已存在的同产品原生单据是否能从反馈详情关联，以及原生详情能否返回反馈。类型支持 `story`、`requirement`、`epic`、`bug` 和 `task`。执行任务的执行必须关联该测试产品。

0.3.0 增加了后台进度核对表。升级前仍需执行当前版本的 `db/install.sql`。在禅道应用根目录手动运行一次核对命令，成功后可由部署环境的调度服务定时调用。Compose 中可用：

```sh
docker compose exec -T -u www-data php php extension/custom/reqintake/bin/sync.php
```

命令只在插件处于已安装状态时更新快照。详情仍读取单据当前状态，并显示最近后台核对时间。单据的进度不会改变反馈的办理状态。

0.4.0 增加反馈修订记录。升级前执行本版 `db/install.sql` 创建修订表。负责人或管理员可在未关闭反馈的详情中修改标题、描述、客户和渠道；详情保留初次提交和历次修订。

0.5.0 增加沟通与转交记录。升级前执行本版 `db/install.sql` 创建记录表。负责人或管理员可在未关闭反馈的详情中记录沟通或转交给具备产品访问和需求池办理权限的账号。转交保留当前状态，并记录原负责人、新负责人、操作者及说明。

0.6.0 支持在反馈详情打开原生研发需求、用户需求和业务需求表单。表单预填产品和标题，正文与附件由操作人在原生表单确认。同一操作的原生单据、承接关系和操作结果在同一数据库事务中保存。重复提交同一操作时返回原单据。每次只创建一张需求，孪生需求模式会被拒绝。升级前执行本版 `db/install.sql` 创建转单操作表。

0.7.0 支持选择同产品的多条反馈后新建一张需求。列表填写共同承接范围，原生表单显示来源编号和承接范围。提交后所有来源均关联同一张单据。来源版本已变化时整批拒绝，可返回列表重新选择。

反馈详情也可打开禅道原生 Bug 表单。产品和标题从反馈带入，影响版本及复现步骤在原生表单填写。成功保存后自动关联原反馈，同一操作重复提交会复用已创建的 Bug。

0.8.0 支持从反馈选择已关联该产品且有权创建任务的执行，再进入原生单任务表单。重复提交会复用已记录的任务 ID。禅道任务模型有独立的提交边界。如果中断发生在原生提交之后、任务 ID 记录之前，同一操作会提示待核对并拒绝再次创建。请在所选执行中核对实际任务，确认后从反馈关联已有任务。

0.9.0 在反馈登记和修订中增加类别、优先级、验收标准。类别和优先级选项沿用原生需求，验收标准先以独立文本保存。单条反馈转需求时将这三项带入原生表单。升级前执行本版 `db/install.sql`，旧反馈自动显示默认类别和优先级。

0.10.0 的描述和验收标准使用独立的禅道富文本编辑器。服务端保留段落、标题、强调、列表和代码等格式。旧版纯文本与历史版本继续正常显示。本版富文本暂不保存图片。升级前执行本版 `db/install.sql` 创建格式记录表。

0.11.0 支持反馈详情上传、下载和移除附件，每个文件最大 5 MiB，以部署的 PHP、Nginx 和 MySQL 限制为准。附件随插件数据库保存，下载须通过反馈读取权限验证。升级前执行本版 `db/install.sql` 创建附件表。富文本内嵌图片仍待接入。

0.12.0 支持在反馈描述和验收标准中保存 PNG、JPEG、GIF 内嵌图片。图片与正文一起保存在反馈及修订中，经反馈页面鉴权后显示。每个富文本字段的提交上限为 4 MiB，含图片编码体积。单条反馈转需求时只带入验收标准文字和格式，图片留在反馈中。

0.13.0 增加来源、来源备注、关键词和预计工时。单条反馈转需求时带入来源、关键词和预计工时，来源备注保留在原反馈。升级前执行本版 `db/install.sql`，旧反馈的新增字段默认为空。

0.14.0 支持在反馈选择一个产品分支或平台及对应模块。切换产品和分支时会更新可选项，保存时校验归属。单条反馈转需求时带入仍有效的分支和模块。升级前执行本版 `db/install.sql` 创建产品范围表。

0.15.0 支持在反馈详情更新下一步、剩余事项以及记录已经发给客户的答复。每次保存会记录经办人和时间，答复还记录对象、渠道和内容。列表显示最新下一步。升级前执行本版 `db/install.sql` 创建办理记录表。

0.16.0 可在详情选择同产品的原反馈编号并按重复关闭，保留当前反馈的独立结案记录和指向原反馈的链接。同一反馈不能关联自身，也不能形成循环。升级前执行本版 `db/install.sql` 创建重复反馈关系表。

## 0.16.0 升级验证

在禅道开源版 22.7 的独立 Compose 测试实例验证，数据库为 MySQL 8.4，表前缀为 `ri_`。

1. 备份测试数据库并确认备份非空。预先应用本版 `db/install.sql`，其中的表前缀替换为实例使用的前缀。
2. 通过后台扩展管理上传校验过的插件 ZIP 并执行升级。PHP-FPM 运行用户需要能写入插件目标路径。测试实例曾因手工部署后文件属主与 PHP-FPM 用户不一致而被安装器拒绝。将插件所在测试目录的属主修正为 PHP-FPM 用户后，原生升级成功。
3. 重启 PHP 容器后完成 HTTP 冒烟测试，覆盖提交、分派、产品表单、五类原生转单、批量转需求、状态、沟通、富文本、附件、答复和重复结案。

4. 通过后台扩展管理停用插件，确认原生产品详情隐藏负责人字段。重新启用后，负责人配置、原反馈及其附件恢复可见，附件下载内容逐字节一致。

升级验证使用了已有数据的测试实例。

### 空库安装与容器重建

使用独立 Compose 项目和全新 MySQL 8.4 数据卷安装禅道 22.7，表前缀为 `ri_`。应用数据库账号按安装器提示显式授予该数据库的建表、建视图及读写权限，通过扩展管理全新安装 0.16.0，插件自动建表。已验证新建产品、提交反馈和上传附件。

使用 [扩展卷配置](../../docker/README.md#持久化本地安装的扩展) 强制重建 PHP 和 Nginx 容器后，插件仍处于已安装状态，原反馈详情可打开，附件可按原链接下载且内容一致。


### 卸载重装和版本回退

在隔离测试实例备份数据库后，通过扩展管理卸载 0.16.0。插件代码被移除，数据库保留。重新安装 0.16.0 后，原反馈和附件恢复可见，附件内容一致。

同一测试实例也验证了卸载 0.16.0 后安装先前构建的 0.15.0，原反馈和附件可读取。随后重新安装 0.16.0 并再次检查数据。该演练验证插件代码回退，数据库保留新增表，旧版界面只能使用其原有功能。生产回退前备份数据库和扩展卷，确认目标版本与保留的表结构兼容。

### 浏览器验收

0.16.1 修复浏览器中的负责人预览。预览请求使用禅道识别的 AJAX 请求头，避免被导航框架重定向。Chromium 已验证切换产品、负责人预览、编辑两个富文本字段、粘贴 PNG、提交和详情回显。测试需要本机 Chromium、Node.js 和 Playwright，并使用待配置负责人的测试产品。

```sh
node plugins/reqintake/tests/browser-smoke.cjs http://127.0.0.1:8097 /path/to/admin-password 'Smoke Product'
```

0.17.0 支持在一个反馈中记录主选分支／平台及其他适用分支／平台，每个分支分别选择模块。历史单分支记录可继续读取。单条反馈转成一张原生需求时预填主选分支和模块，其他适用范围保留在原反馈。升级前执行本版 `db/install.sql` 创建分支范围表。Chromium 验证了附加分支及模块的选择、提交和回显。

0.20.0 在地盘显示当前账号最近五条未关闭的待处理反馈，并提供直达详情和「待我处理」列表的链接。入口沿用需求池访问权限和产品可见范围。

### 调度恢复验收

在独立 Compose 测试实例，使用 0.20.0 安装包和 `ri_` 表前缀运行可选的 [进度核对服务](../../docker/README.md#定时核对需求池进度)。验证先写入研发需求的进度快照，再停止调度，将测试目标标为删除，确认快照尚未变化。重新启动后，快照标记目标不可用。恢复目标并更新原生阶段后，下一轮核对恢复可用并记录新阶段。来源反馈保持「跟进中」。

0.20.1 在反馈详情和后台进度快照中保留原生任务关闭原因。升级无需数据库迁移。

0.21.0 在禅道原生办理动作写入操作记录后核对该单据的承接进度。同一次请求对同一目标只核对一次，在原生保存完成后读取已提交的数据。Compose 定时服务继续兜底核对全部承接关系。升级无需数据库迁移。

0.21.1 单条需求或 Bug 转单在不同登录会话之间共用操作记录。同一反馈版本转为同一类型时，并发提交返回同一原生编号。原有会话中的转单重试继续兼容旧操作记录。升级无需数据库迁移。

0.21.2 用唯一键直接预留任务转单操作，重试读取当前已提交的承接关系。持久记录包含真实任务编号时，重试可补齐承接关系。记录只有预留标记时，表单显示「待核对」并阻止重复造单。升级无需数据库迁移。

0.22.0 新建和编辑反馈可选所属计划。计划按产品和主选分支筛选，单条转需求时带入仍可用的计划，历史计划编号随反馈修订保留。升级前执行本版 `db/install.sql` 创建计划记录表。

0.23.0 在反馈新建和编辑表单新增「抄送给」，使用禅道账号多选控件。反馈保存抄送名单和修订版本。单条转需求时在原生表单预填有效账号，由操作者确认。升级前执行本版 `db/install.sql` 创建抄送记录表。

0.24.0 单条转单预填最新反馈正文。三类需求同时预填独立验收标准，Bug 预填重现步骤，任务预填描述。保留正文格式，内嵌图片、附件及来源备注保留在原反馈。批量转单由操作者填写共用正文。升级无需数据库迁移。

0.24.1 在编辑反馈的字段校验失败后展开编辑表单并保留该次输入，保留版本检查。升级无需数据库迁移。

### 0.24.1 升级复验

在原有 0.20.0 的独立 Compose 测试实例（禅道开源版 22.7、MySQL 8.4、`ri_` 前缀）备份数据库，应用当前建表脚本，再从后台扩展管理上传校验过的 0.24.1 ZIP。安装器报告升级成功。重启 PHP 后确认插件版本、原有反馈及附件。通过扩展卷配置强制重建 PHP 和 Nginx 后再次检查，反馈可读取，附件下载字节与升级前一致，手动进度核对命令成功执行。

0.25.0 增加反馈字段「客户使用版本」。客服可记录客户实际安装的产品版本，字段随反馈修订保存，与所属计划和原生需求版本独立。升级前执行本版 `db/install.sql` 创建客户版本记录表。
